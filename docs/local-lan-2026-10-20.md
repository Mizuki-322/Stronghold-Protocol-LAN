# Local LAN changes — 2026-10-20

This fork starts from the fan remake's v0.3.1 release. These are user-requested local changes, not claims about official Arknights rules or the upstream release.

## Bond visibility and tracking

The in-match 本局信息 drawer lists core bonds with at least one unbanned visible member. A partially banned bond stays in the list, including one reduced to three available operators. A bond with zero available listed operators is omitted from this list, although special counting sources can still activate it. The banned-operator information remains below it. Selecting a listed bond opens its detail popup.

The popup can track or untrack a core bond for the current match. Multiple bonds may be tracked. The player's bond strip pins tracked entries, including a zero-member entry; matching operator cards in the shop and reward offers show a tracking cue based on their actual bond IDs. Tracking is local to the player's browser and is cleared when a new match screen starts. Teammate bond views do not inherit it.

## Bond pool exclusions

The mode's fixed `inactiveBondIds` (in 标准模拟) and the match's drawn exclusions only remove operators whose every bond lies in the excluded set. They do not disable the bond effect itself. A remaining multi-bond operator, 变形同构体, 调和, or another valid count source may still activate it. 绝技 counts elite operators even though it has no listed members. The match-info view dims only bonds that actually lost listed operators and shows the banned operators separately. 险境、绝境、终极 have no fixed inactive-bond list in the current data; they use the same operator-pool rule for their random exclusions.

## Optional untimed co-op rest phase

The private co-op room host can turn 休整期不限时 on before starting. It is off by default, visible to all room members, and changing it clears the other players' Ready states. The choice is fixed when the match starts and resets when it ends. It removes only the PREP deadline; every other phase keeps its timer. All alive players preparing still ends the phase. Solo and one-human matches already had untimed PREP. This build has no automatic teammate matchmaking; rooms are joined by invitation code or filled manually with AI.

After the host presses Start with this option on, every real player sees a confirmation dialog. The match begins only after all real players accept. Built-in AI and external AI seats are excluded. A refusal, 60-second timeout, disconnect, or change to the player roster returns the room to its ready screen, turns the option off, and clears every human player's Ready state.

## External DeepSeek player

An external Node process can join a normal, unmodded co-op player seat through the same `/ws` protocol as a browser. It uses the `agent: true` hello flag, accepted only from loopback or a private LAN address, and appears as **外部 AI 玩家** in the lobby. The flag does not grant hidden match information or extra gameplay actions. The server runs this seat's battles because the external process has no browser simulator. Other players' fields remain read-only; it may start watching another normal field only after its own battle finishes. A rejected action returns the regular server error code and detail to the model's next observation.

The in-match emote panel now includes human text chat with a 20 Unicode-character limit. An external AI seat can send up to 80 characters. Both use server-side validation and a three-second text-chat cooldown. Emotes retain their existing whitelist and cooldown. The agent adds a local 15-second text-chat cooldown to avoid replying to every line.

To run it, start the isolated server, create a **co-op** room in the browser, and copy its four-character room code. In a separate terminal, set `DEEPSEEK_API_KEY`, `SP_AI_ROOM`, and `SP_AI_SERVER` (for example `ws://127.0.0.1:17878/ws`), then run `node scripts/deepseek-agent.mjs` from this repository. Leave that process running for the match. The room host starts the match after the AI seat becomes ready. `DEEPSEEK_MODEL` defaults to `deepseek-flash`; `DEEPSEEK_API_URL` can point at an API-compatible test endpoint. Do not put the API key in the repository.

The agent sends its player-visible room/match state, own private shop/board, public map and known card/enemy records, and recent chat to the configured DeepSeek API. It never reads another player's private view. It can request a 2D tactical PNG of its own map/board twice per round; that image is then included in the next DeepSeek request. On Windows it uses Edge by default; set `SP_AI_CHROME` to another Chromium executable if needed. This is a tactical rendering of visible state, not a capture of the game's 3D canvas.

`g.battleStats` returns only the caller's own current field totals (`m.battleStats`), including live damage when the server simulates the field. A browser-run field may have no server-side live damage until its result arrives. The agent also sees its cumulative damage from `m.private.stats` after settlement. These numbers may include 联防 in the settled cumulative total.

The standalone agent currently uses the vanilla data files in this checkout. A room with gameplay plugins is not supported: its content download/consent flow and modified game data are not loaded by this process. The browser's existing built-in AI seats remain separate from this external DeepSeek seat.

If three consecutive DeepSeek requests fail, the process enables the game's built-in AI control for that seat so an untimed room can continue. It keeps checking the API and turns built-in control off when a model decision succeeds again. This fallback changes the seat's actions, so the console prints when it activates.
